GNR8 AI Website Engine Architecture Spec (founder level)

1. Purpose

AI Website Engine is:

The intelligence layer that understands, improves, evolves, and operates websites inside GNR8.

It is NOT:
	•	a page builder
	•	a template generator
	•	a chat toy
	•	a pure LLM wrapper

It is:
	•	a semantic decision system
	•	a website optimization engine
	•	an autonomous (risk-bounded) operator layer

⸻

2. Role in GNR8 V1

In V1 AI Engine exists to:
	1.	Analyze migrated sites
	2.	Suggest improvements
	3.	Execute approved transformations
	4.	Learn from agency patterns
	5.	Enable controlled autopilot

Migration creates structured input.
AI Engine creates strategic evolution.

⸻

3. Core Runtime Loop

Canonical loop:

Structured Site Model
→ Semantic Understanding
→ Opportunity Detection
→ Proposal Generation
→ Operator Approval
→ Transformation Execution
→ Measurement
→ Learning
→ Repeat

This loop is the heart of GNR8.

⸻

4. AI Engine Layers

4.1 Semantic Understanding Layer

Transforms structured model into:
	•	business profile
	•	UX maturity score
	•	funnel architecture
	•	messaging clarity
	•	content quality signals
	•	conversion intent signals

This is:

Hybrid:
	•	deterministic signals
	•	LLM interpretation
	•	heuristic scoring

Output:

→ Site Semantic Graph

⸻

4.2 Opportunity Detection Engine

Detects:
	•	missing sections
	•	weak CTAs
	•	poor hierarchy
	•	outdated design patterns
	•	SEO gaps
	•	performance risks
	•	trust signal gaps

Produces:

→ Opportunity objects

Each opportunity includes:
	•	impact estimate
	•	confidence
	•	risk classification
	•	required transformation type

⸻

4.3 Proposal Generation Engine

Converts opportunities into:
	•	concrete change proposals
	•	UI/layout/content changes
	•	design token adjustments
	•	structure modifications

Proposals must be:
	•	human understandable
	•	diffable
	•	reversible
	•	scoped

⸻

4.4 Transformation Planner

Groups proposals into:
	•	change waves
	•	atomic operations
	•	safe execution order

Planner ensures:
	•	no layout breakage
	•	no semantic regression
	•	dependency awareness

⸻

4.5 Transformation Executor

Executes approved changes on:

Structured Site Model.

Executor is:

Deterministic.

AI decides WHAT.
Executor decides HOW.

⸻

4.6 Measurement Layer

Tracks:
	•	conversion proxy metrics
	•	UX score improvements
	•	SEO signal changes
	•	engagement signals
	•	agency-defined KPIs

Measurement feeds:

→ learning loop.

⸻

4.7 Learning Layer

Learns from:
	•	approved vs rejected proposals
	•	outcome signals
	•	agency patterns
	•	industry clusters

Builds:
	•	pattern intelligence
	•	proposal priors
	•	confidence calibration

⸻

5. AI Modes

5.1 Analysis Mode

Read-only.

Used for:
	•	initial site understanding
	•	reporting
	•	opportunity mapping

⸻

5.2 Suggestion Mode (V1 default)

AI proposes.

Human approves.

This is:

Primary production mode.

⸻

5.3 Assisted Edit Mode

User instructs:

“Improve hero”
“Make more modern”
“Optimize for conversions”

AI generates:

→ scoped transformation plan.

⸻

5.4 Autopilot Mode (V1 limited)

Allowed only for:
	•	low-risk changes
	•	content tweaks
	•	token normalization
	•	minor UX improvements

High-risk always requires approval.

⸻

6. Risk Tier Model

Every transformation classified:

Tier 0 — Safe Auto
	•	spacing tweaks
	•	token normalization
	•	typo fixes
	•	minor layout polish

Tier 1 — Assisted Auto
	•	section reordering
	•	CTA improvements
	•	copy refinement

Tier 2 — Approval Required
	•	layout restructuring
	•	design system changes
	•	navigation changes

Tier 3 — Forbidden Auto
	•	domain changes
	•	billing changes
	•	destructive content deletion
	•	legal pages

⸻

7. AI Governance Principles

AI must be:
	•	explainable
	•	auditable
	•	reversible
	•	diffable
	•	confidence-scored

Every change must produce:
	•	reasoning trace
	•	impact hypothesis
	•	rollback path

⸻

8. Semantic Graph

Core internal representation:

Site → Pages → Sections → Components → Content → Tokens → Signals

Plus:
	•	business attributes
	•	marketing intent
	•	funnel stage mapping
	•	UX maturity vectors

This graph is:

AI substrate.

⸻

9. Interaction Model

Primary interface:

AI chat as command center.

User can:
	•	ask questions
	•	request changes
	•	run analyses
	•	approve plans
	•	trigger migrations
	•	enable autopilot

No visual builder required.

⸻

10. AI Execution Constraints

AI must NOT:
	•	invent structure without basis
	•	hallucinate business facts
	•	override human approvals
	•	break semantic integrity

AI must:
	•	operate on structured model
	•	respect migration constraints
	•	maintain design system coherence

⸻

11. Multi-Tenant Intelligence

Learning must be:
	•	anonymized
	•	pattern-based
	•	non-leaking

Agency-specific intelligence allowed.

Cross-agency intelligence:

Only via aggregated patterns.

⸻

12. AI Data Sources

AI uses:
	•	migrated site structure
	•	content signals
	•	analytics (future)
	•	performance metrics
	•	industry embeddings
	•	global design trend priors

⸻

13. AI Output Guarantees

Every proposal must include:
	•	reasoning
	•	expected impact
	•	risk tier
	•	transformation diff
	•	confidence score

⸻

14. Autopilot Philosophy

Autopilot is:

Gradual trust system.

Starts with:

tiny improvements.

Earns right to:

bigger decisions.

⸻

15. Founder Directive

AI Engine must make GNR8:
	•	smarter over time
	•	safer than agencies
	•	faster than builders
	•	more strategic than templates

If done right:

GNR8 becomes:

→ AI operating system for websites.
