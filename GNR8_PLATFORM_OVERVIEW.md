# GNR8 Platform Overview

## Introduction

GNR8 is an AI-native Website Operating System designed to govern, evolve, and operate digital experiences throughout their entire lifecycle.

Unlike traditional website builders, content management systems, or migration tools, GNR8 is built around a continuous operational model.

The platform understands websites, stores, providers, environments, governance boundaries, and future AI execution paths as parts of a single operational system.

Its purpose is not simply to create websites.

Its purpose is to operate them.

---

# The Core Principle

The central design principle behind GNR8 is simple:

Governance comes before execution.

Before any system is allowed to make changes, it must first understand:

- what exists
- what is connected
- what is allowed
- what is restricted
- who owns it
- how changes are approved
- how changes are audited

This philosophy influences every part of the platform.

---

# Control Plane and Execution Plane

GNR8 separates operational intelligence from operational action.

## Control Plane

The Control Plane is responsible for:

- understanding systems
- maintaining state
- provider governance
- environment awareness
- AI routing policies
- credential governance
- readiness evaluation
- operational visibility

The Control Plane knows what should happen.

It does not directly execute changes.

---

## Execution Plane

The Execution Plane is responsible for:

- deployments
- provider mutations
- content updates
- infrastructure changes
- AI-assisted operations

The Execution Plane performs actions only after governance requirements are satisfied.

Today, execution remains intentionally restricted.

The platform currently focuses on governance, visibility, orchestration, and decision modeling.

---

# Website Lifecycle

GNR8 manages websites as evolving systems.

The lifecycle begins with acquisition and continues through continuous operation.

Typical lifecycle:

1. Import
2. Analysis
3. Structure preparation
4. Layout preparation
5. Preview generation
6. Approval
7. Execution
8. Continuous operation
9. Continuous optimization
10. Continuous evolution

The platform maintains operational understanding throughout the entire lifecycle rather than treating launch as the endpoint.

# Environment Awareness

Digital systems rarely exist in a single environment.

GNR8 introduces environment-aware governance through:

- global scope
- sandbox scope
- preview scope
- staging scope
- production scope

This allows future execution systems to understand operational boundaries before changes are made.

Environment awareness exists before environment execution.

---

# Credential Governance

Credentials are treated as governed assets rather than implementation details.

The platform distinguishes between:

- credential references
- credential ownership
- credential bindings
- secret resolution
- provider authorization

Current platform direction intentionally separates credential modeling from credential execution.

This enables future multi-tenant operation without exposing secrets throughout the platform.

---

# AI Routing Architecture

GNR8 is designed as a multi-provider AI platform.

The goal is not to depend on a single model vendor.

Instead, the platform maintains:

- AI provider metadata
- routing policies
- capability definitions
- governance constraints
- future evaluation rules

Current AI providers include:

- OpenAI
- Anthropic
- Gemini
- Groq
- Mistral

---

## AI Routing Policy Layer

Different AI tasks require different capabilities.

Examples:

- migration planning
- architecture review
- visual understanding
- fast generation
- EU-sensitive workloads
- tool orchestration

The routing policy layer defines preferred providers, fallback providers, and routing strategies for each task class.

Today, this exists as a deterministic preview model.

No live provider routing is performed.

---

## AI Routing Evaluator

The platform includes a routing evaluator preview layer.

The evaluator can:

- classify task types
- apply routing policies
- produce routing recommendations
- evaluate governance constraints

The evaluator currently operates in preview mode only.

Execution remains blocked.
