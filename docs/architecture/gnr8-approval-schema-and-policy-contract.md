# GNR8 Approval Schema and Policy Contract (AAF-2)

## Purpose

This contract defines implementation-ready approval persistence and policy semantics for the MVP Audit, Approval, and Evidence foundation. It is a schema design document only and does not create migrations or runtime behavior.

## Canonical Storage Decision

Approvals must be stored in new canonical Supabase/Postgres control-plane tables. Existing runtime, migration, domain, provider, billing, content, and Command Center records may be linked as subject/source refs, but they are not approval truth.

Heavy artifacts must be referenced through immutable evidence package records, not embedded as mutable approval payloads.

## Required Approval Statuses

The MVP approval status enum must include exactly these AAF-1 statuses:

| Status | Meaning | Terminal |
|---|---|---|
| `requested` | Approval has been requested and awaits decision or policy outcome. | No |
| `granted` | Human approver granted the scoped decision. | Yes unless revoked, expired, or superseded by later link |
| `rejected` | Human approver rejected the scoped decision. | Yes |
| `revoked` | Previously granted decision was revoked by an authorized actor. | Yes |
| `expired` | Previously valid decision is outside its freshness/expiration window. | Yes |
| `superseded` | Later subject state, evidence, or policy made the decision obsolete. | Yes |
| `cancelled` | Request was withdrawn or invalidated before approval. | Yes |
| `not_required_by_policy` | Policy evaluation explicitly determined no approval was required for this exact action and subject. | Yes |

Absence of a row never means `not_required_by_policy`.

## Policy Result Contract

Policy evaluation must return and persist:

- `approval_required`: a matching effective approval is required and not yet present.
- `approval_not_required_by_policy`: no human approval is required for this exact subject/action/scope; persist a decision with `not_required_by_policy`.
- `approval_blocked`: policy forbids the action regardless of approval.
- `approval_stale`: evidence or approval freshness is invalid.
- `approval_superseded`: a newer subject/evidence/policy version invalidated the decision.
- `emergency_exception_required`: incident path may proceed only through emergency scope.
- `emergency_exception_granted`: emergency scope is effective.
- `policy_error`: evaluator failed and the action must fail closed.

## Retention Vocabulary

The canonical MVP retention classes for approval, policy, and linked evidence records are:

- `short_operational`: transient diagnostics and non-privileged traces.
- `mvp_operational`: ordinary approval/evidence/audit records needed for MVP operations.
- `security`: identity, auth, authorization, security-sensitive denials, and security incident diagnostics.
- `compliance_long`: publish, rollback, domain, cost exception, incident, and admin exception evidence/audit.
- `legal_hold`: records explicitly retained by superadmin/legal policy.

## Failure Behavior

Approval request, decision, policy evaluation, and evidence link writes must fail closed for privileged actions when required refs cannot be persisted. UI callers may show a request failure, but execution routes must independently validate the persisted canonical state before mutation.
