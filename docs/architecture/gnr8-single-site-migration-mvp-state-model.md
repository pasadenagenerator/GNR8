# GNR8 Single-Site Migration MVP State Model

MVP-2 canonical state model for one-site-at-a-time migration, improvement, subscription/hosting activation, launch, publish, rollback readiness, and closeout.

This is documentation and architecture only. It does not implement stored state, TypeScript, JavaScript, SQL, API routes, workers, providers, DNS/domain behavior, billing/Stripe behavior, publish/rollback behavior, Command Center behavior, Ops Inbox behavior, public runtime behavior, AI execution, storage, auth, or client portal behavior.

## Model Scope

This state model applies to one website migration candidate under one selected client. It supersedes batch-level MVP-1/BMF-1 state framing for immediate MVP proof. Batch states remain future scaling architecture and are not required for MVP-2 acceptance.

Command Center represents state as a derived operator projection. Ops Inbox represents blockers/exceptions as derived work items. Neither surface is source truth.

## Approval And Readiness Separation

| Concept | Meaning | Not equivalent to |
| --- | --- | --- |
| Client approval | Client-visible acceptance of clone, content, improvement, or launch material within a stated scope. | Publish activation approval, domain readiness, subscription readiness. |
| Content approval | Approval of specific content/visual result or published override plan. | Launch approval or publish activation. |
| Launch approval | Business signoff that the site may proceed toward launch after prerequisites. | Active pointer mutation unless explicitly scoped as publish activation. |
| Publish activation approval | Governed approval to activate a specific version/target/domain. | DNS mutation, rollback, batch publish, or AI execution. |
| DDOM readiness | Domain/DNS/custom-domain prerequisite evidence and freshness. | Any approval. |
| Subscription/hosting readiness | Commercial entitlement and hosting operating prerequisite. | Publish approval or launch signoff. |

| `source_capture_started` | Capture/import is running or explicitly queued for this one site. | Migration operator/system capture service. | Capture job/run record and migration/capture stage state. | Source URL, input refs, actor/system id, capture policy. | Capture/job approval if required by operator policy. | `source_capture_completed`, `source_capture_failed`. | Clone generation, proposal, publish. | Capture in progress with stage diagnostics. | Stuck or failed capture only. | Capture started, input refs, correlation/idempotency. |

| `source_capture_failed` | Capture failed or produced unusable evidence. | Migration operator/technical operator. | Capture run failure record. | Failed stage, error, source availability, retry eligibility, source refs. | Retry/replay approval if retry is not automatic. | `source_capture_started`, `migration_failed`, `migration_cancelled`. | Clone/proposal/publish/subscription states. | Failure with retry/defer options. | `source_capture_failed`. | Failure reason, retry decision, actor, refs. |

| `clone_review_required` | Human must judge clone fidelity before improvements. | Migration/content/technical operator; client if required. | Clone review record and evidence package. | Source-vs-clone screenshots, route coverage, text/image/font/layout/metadata checklist, fidelity score. | Clone acceptance or client review approval where required. | `improvement_proposal_started`, `clone_revision_required`, `source_capture_started`, `migration_failed`. | Improvement implementation, content approval, publish. | Fidelity review lane with score/status. | `clone_review_required`. | Review requested/completed, accepted limitations. |
| `clone_revision_required` | Clone needs corrections before proposal/improvement. | Migration/content/technical operator. | Revision request plus clone/capture refs. | Requested fixes, affected pages/assets/content/styles, reason, owner. | Approval only if revision changes scope/risk materially. | `clone_generation_started`, `clone_review_required`, `migration_failed`, `migration_cancelled`. | Proposal approval, publish. | Revision blocker and assignee. | `clone_revision_required`. | Revision requested/completed, diffs, refs. |
| `improvement_proposal_started` | Improvement proposal is being drafted from accepted clone/source evidence. | Migration operator/strategy/content operator; AI advisory if used. | Proposal draft artifact/workflow refs. | Accepted clone refs, source evidence refs, business goal, limitations. | None to draft; AI output advisory only. | `improvement_proposal_ready`, `clone_review_required`, `migration_failed`. | Improvement implementation or publish. | Proposal drafting status. | None unless stale/blocked. | Proposal generation start, inputs, AI/provider refs if any. |
| `improvement_proposal_ready` | Proposal is ready for human approval/rejection. | Operator/client reviewer. | Immutable proposal artifact and approval request refs. | Proposal artifact, scope, expected changes, risks, evidence refs. | Proposal approval required before implementation. | `improvement_proposal_approved`, `improvement_proposal_rejected`, `improvement_proposal_started`. | Implementation, content approval, publish. | Proposal ready with decision needed. | `approval_needed`. | Proposal ready, evidence package, approval request. |
| `improvement_proposal_approved` | Proposal scope is accepted for implementation. | Client/internal approver according to policy. | Approval decision scoped to proposal. | Approval decision, proposal refs, approver, scope, limitations. | Proposal approval is present; later approvals still required. | `improvement_implementation_started`, `improvement_proposal_started`, `migration_cancelled`. | Publish, domain readiness, subscription as approval shortcut. | Approved proposal status. | None unless implementation not started/stale. | Approval granted with exact scope and refs. |
| `improvement_proposal_rejected` | Proposal is rejected or requires a new proposal. | Client/internal approver. | Rejection decision scoped to proposal. | Rejection reason, proposal refs, requested changes if any. | Rejection recorded. | `improvement_proposal_started`, `migration_cancelled`, `migration_failed`. | Improvement implementation from rejected proposal. | Rejected proposal status. | Proposal revision needed if continuing. | Rejection decision and reason. |
| `improvement_implementation_started` | Approved improvements are being implemented. | Content/technical/migration operator or governed implementation service. | Implementation task/state plus approved proposal refs. | Approved proposal, change list, target version/content refs. | Existing proposal approval; extra scope needs new approval. | `improvement_implementation_completed`, `improvement_proposal_started`, `migration_failed`. | Publish or content approval before implementation completes. | Implementation progress and scope. | Implementation blocker if stalled. | Implementation start, scope refs, actor. |
| `improvement_implementation_completed` | Approved improvements have been applied to a candidate. | Implementation operator/runtime service. | Improved version/artifact/content override refs. | Diff, improved artifacts, content override refs, diagnostics, proposal approval refs. | None to complete; review/approval later. | `improved_preview_ready`, `content_review_required`, `improvement_implementation_started`. | Domain/subscription/publish without preview/review. | Improved candidate ready. | Content review needed if preview/review missing. | Implementation completed with before/after refs. |
| `improved_preview_ready` | Improved site preview is available for final review. | Runtime/preview service and operator. | Preview generated from improved version/artifact/override state. | Preview URL, smoke/readiness, visual/content QA notes, diagnostics. | Sharing externally may require policy approval. | `content_review_required`, `content_approved`, `improvement_implementation_started`. | Domain/subscription/publish without content approval. | Preview ready with QA checklist. | `content_review_required`. | Preview generated/shared/viewed where relevant. |
| `content_review_required` | Final content/visual/functionality review is required. | Content operator/client reviewer/account owner. | Content/visual review and approval request. | Improved preview, diff, content/visual checklist, forms/widgets/SEO notes. | Content/client approval if client-visible. | `content_approved`, `improvement_implementation_started`, `migration_cancelled`. | Domain readiness ready, subscription created, publish. | Review required with owner. | `content_review_required` or `approval_needed`. | Review requested, comments, decision refs. |
| `content_approved` | Final content/visual result is accepted. | Client/internal approver. | Content/client approval decision. | Approval record, preview refs, accepted limitations, content override state. | Content approval present; launch/publish still separate. | `domain_readiness_required`, `subscription_required`, `launch_approval_required`, `improvement_implementation_started`. | Publish without domain/subscription/launch/publish activation approval. | Content approved badge. | None unless other blockers remain. | Approval granted with evidence refs. |
| `domain_readiness_required` | Intended domain/custom-domain/DNS/SSL readiness must be prepared or excepted. | Technical/domain operator; client DNS owner where applicable. | Domain binding, DNS instruction, DDOM readiness source workflow. | Domain intent, owner, DNS instructions, Vercel/custom-domain snapshot where applicable, SSL/readiness, blockers. | Domain action/exception approval as required. | `domain_readiness_ready`, `content_approved`, `migration_failed`, `migration_cancelled`. | Publish-ready/published without readiness or exception. | Domain lane with blockers/freshness. | `domain_action_needed`, `dns_verification_failed`, `approval_needed`. | Instructions generated/shared, checks, evidence, exceptions. |

| `published` | Improved site is active on intended target/domain. | Publish activation workflow/runtime service. | Active pointer, runtime site version/artifact, published overrides, publish event, publish target. | Before/after active pointer, public URL, publish approval, domain/subscription refs, smoke verification start. | Publish activation approval completed. | `rollback_available`, `migration_closed_out`, `migration_failed` if incident/failure, `content_review_required` for future changes. | Re-enter clone/proposal states as same migration without new change cycle. | Live status and active version. | Incident/publish defect only. | Publish completed with before/after refs and actor. |
| `rollback_available` | Recovery target or rollback plan is recorded and verified. | Technical/publish operator. | Runtime active pointer history, previous version/artifact refs, content history, recovery plan. | Known-good target, verification, limitations, incident owner. | None until rollback execution. | `migration_closed_out`, `migration_failed`, `published`. | Closeout without rollback evidence. | Rollback readiness present. | Recovery evidence blocker if missing. | Rollback readiness recorded/verified. |
| `migration_closed_out` | Single-site migration is complete and validation data is recorded. | Migration operator/account owner. | Closeout record plus audit/evidence refs. | Final URL, source/clone/proposal/improvement/domain/subscription/publish/rollback refs, metrics, defects, costs, time. | Closeout approval if exceptions or critical incidents occurred. | Terminal unless future reactivation/change workflow is opened. | Silent mutation, batch aggregation as proof without per-site closeout. | Closed status and summary. | No open items unless separate incident. | Closeout created with metrics and confirmation. |
| `migration_failed` | Migration cannot continue or launch under MVP rules. | Migration operator/superadmin for critical failures. | Failure record and audit/evidence refs. | Failure taxonomy, last good state, source refs, impact, retry/defer/no-go decision. | Superadmin/owner approval for critical no-go or unsupported continuation. | `source_capture_started`, `site_candidate_created`, `migration_cancelled`, terminal no-go. | Publish, subscription/hosting activation as success. | Failed with reason and recovery option. | Failure item until closed by source decision. | Failure/no-go decision, evidence, owner. |
| `migration_cancelled` | Migration intentionally stopped before completion. | Client/account owner/migration operator. | Cancellation record. | Reason, current state, client/site/source refs, cleanup/handoff notes. | Client/account/admin approval depending on scope. | Terminal unless new candidate/change workflow starts. | Publish, billing activation, closeout as success. | Cancelled status. | None after source cancellation decision. | Cancellation decision and final refs. |

## Prohibited Shortcuts

- `site_candidate_created` to clone/proposal/publish without source capture.
- Any capture state to proposal or improvement without source evidence review or accepted evidence.
- Clone generation to improvement implementation without clone review/acceptance.
- Proposal ready to implementation without proposal approval.
- Proposal approval to publish without implementation, improved preview, content approval, domain readiness, subscription/entitlement, launch approval, and publish activation approval.
- Content approval to publish without domain readiness, subscription/hosting entitlement, launch approval, and publish activation approval.
- Domain readiness to publish without launch and publish activation approval.
- Subscription creation to publish without hosting entitlement, launch approval, and publish activation approval.
- Launch approval to active pointer mutation unless explicitly scoped as publish activation approval.
- Publish activation without governed source refs, evidence, and human approval.
- Ops Inbox item closure without canonical source transition or audited source-owned decision.
- AI/provider output mutating any state directly.

## State Groups

| Group | States |
| --- | --- |
| Intake | `site_candidate_created` |
| Source capture/evidence | `source_capture_started`, `source_capture_completed`, `source_capture_failed`, `source_evidence_review_required` |
| Clone | `clone_generation_started`, `clone_generation_completed`, `clone_review_required`, `clone_revision_required` |
| Proposal | `improvement_proposal_started`, `improvement_proposal_ready`, `improvement_proposal_approved`, `improvement_proposal_rejected` |
| Improvement/content | `improvement_implementation_started`, `improvement_implementation_completed`, `improved_preview_ready`, `content_review_required`, `content_approved` |
| Domain/commercial readiness | `domain_readiness_required`, `domain_readiness_ready`, `subscription_required`, `subscription_created`, `hosting_entitlement_ready` |
| Launch/publish/recovery | `launch_approval_required`, `publish_ready`, `published`, `rollback_available` |
| Terminal/exception | `migration_closed_out`, `migration_failed`, `migration_cancelled` |

## Command Center Projection Contract

Command Center must show the current single-site state, owner, next required source-owned action, evidence freshness, clone/proposal/improvement status, domain readiness, subscription/hosting readiness, launch approval, publish readiness, rollback readiness, audit refs, and prohibited actions with reasons.

Command Center must label batch/factory surfaces as future scale when used for MVP-2 context. It cannot become source truth for state, approval, domain readiness, subscription, publish, rollback, or closeout.

## Ops Inbox Projection Contract

Ops Inbox may derive items such as:

- `source_capture_failed`
- `source_evidence_review_required`
- `clone_review_required`
- `clone_revision_required`
- `approval_needed`
- `content_review_required`
- `domain_action_needed`
- `dns_verification_failed`
- `subscription_required`
- `hosting_entitlement_needed`
- `publish_ready`
- `publish_failed`
- `recovery_evidence_needed`
- `audit_evidence_gap`

Ops Inbox is derived-only. Items resolve only when source-owned state changes or an audited source-owned decision supersedes the condition.
