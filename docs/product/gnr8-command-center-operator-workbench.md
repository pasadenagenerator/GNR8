# GNR8 Command Center Operator Workbench

CCO-1 product workflow for the GNR8 MVP Command Center and derived Ops Inbox.

This is documentation and architecture only. It does not implement Command Center UI, Ops Inbox, APIs, schemas, migrations, queues, workers, approvals, audit persistence, runtime behavior, billing, DNS/domain mutation, publish/rollback changes, storage, AI execution, Workspace, Evolution, thumbnails, or Generated Proposal Bundles.

## Product Position

Command Center is the daily operator workbench for migrating and operating approximately 200 static or mostly static public websites. Ops Inbox is the derived exception/action queue inside that workbench.

Specialized admin, review, Workspace, Evolution, hosting, provider, and content pages are drilldowns unless a later architecture decision adopts one as a primary operator surface.

## Daily Operator Workflow

Operators start in Command Center Overview:

1. Check portfolio health, critical incidents, paused batches, launch blockers, and cost anomalies.
2. Open Ops Inbox filtered to their role.
3. Resolve critical/high work first.
4. Monitor active migration batches and site review queues.
5. Escalate missing approvals, domain owner actions, critical failures, and cost exceptions.
6. End with batch/site closeout and audit/evidence gaps.

## Product Guardrails

- Command Center is the primary MVP operator workbench.
- Ops Inbox is derived-only and not source of truth.
- Every operator action shows why it is allowed or prohibited.
- Publish and rollback are separate approval-gated side effects.
- Domain/DNS visibility is snapshot/instruction/check visibility, not live registrar mutation.
- Cost visibility is internal operating visibility, not full Stripe/customer billing.
- Workspace, Evolution, thumbnails, Generated Proposal Bundles, Website Understanding, Source Content and Visual Continuity, AI outputs, provider payloads, and external workflow snapshots are drilldown evidence only.
