## Result

Two synthetic single-page businesses were generated through the real Astro build/export path, converted by the MVP 06 bridge, selected explicitly by the unified preview renderer, and compared with equivalent proof-only `html-static-artifact` bundles generated by the existing deterministic artifact builder. Current CHS/ARIS previews, Airship drafts/candidates, application routes, persistence, publish paths, live pointers, DNS, providers, billing, environment configuration, and customer data were not read or changed.

MVP 07 originally remained `needs_fixes` because the fallback renderer lost the shared contact heading and emitted fragment links without matching target IDs. MVP 07a repaired those two defects and reran the same fixtures and acceptance criteria through both actual rendering paths. All four comparison rows and all eight desktop/mobile browser captures now pass, so the comparison is ready for further internal evaluation within the existing proof boundary.

## MVP 07a root causes and minimal repair

- Fallback title selection recursively traversed alphabetically sorted properties before preserving direct section semantics. Nested body/link/card strings could therefore replace a direct `sectionProps.title` or `heading`. Direct fields now use the documented precedence `title` → `heading` → `headline` → `name` → `label`; when none exists, the historical recursive first-text behavior is unchanged.
- Canonical wrappers exposed `data-gnr8-section-id` only. The first occurrence of each non-empty canonical section identifier now also receives the exact HTML-escaped DOM `id`; the data attributes remain unchanged and repeated identifiers do not create duplicate targets. Current generated fallback and Airship inner markup contain no nested IDs, so no existing target was renamed or duplicated.

Airship generation, legacy-summary rendering, metadata, preview selection, theme handling, card layout, brand semantics, ecommerce, and multi-page behavior were not otherwise changed.
