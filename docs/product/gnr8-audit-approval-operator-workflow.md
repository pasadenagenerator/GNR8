# GNR8 Audit And Approval Operator Workflow

AAF-1 operator-facing approval and audit workflows for the GNR8 MVP.

This is documentation and product architecture only. It does not implement UI, APIs, approvals, audit, Command Center, Ops Inbox, migrations, workers, domain/DNS, publish, rollback, billing, AI, Workspace, Evolution, Generated Proposal Bundle, thumbnail, asset storage, or deployment behavior.

## Product Principles

- Operators approve scoped decisions, not badges or projections.
- Approvers must see evidence packages with freshness labels and limitations.
- Command Center represents action readiness but does not authorize actions by itself.
- Ops Inbox is a derived work queue and cannot become approval truth.
- Audit timeline review is read-only and must label partial timelines.
- Emergency action is exceptional and must create compensating audit.

## Command Center Rules

- Display approval scope, status, evidence package freshness, expiration, and prohibited actions.
- Disable actions when canonical source state, role permission, approval, audit, evidence, or freshness is unclear.
- Label partial timelines and partial read models.
- Show next required gate rather than a single coarse green status.
- Never display launch signoff as publish activation approval.
- Never display domain readiness as DNS mutation approval.

## Ops Inbox Rules

- Create items from canonical blockers and approval needs.
- Resolve items only when canonical source changes or an audited decision records why work is no longer needed.
- Include source refs, owner role, severity, evidence package requirement, and completion condition.
- Do not store independent approval truth.

## Explicit Deferrals

- Operator UI implementation.
- Notification routing.
- Customer-facing review portal.
- Connected external workflow mutation.
- AI-assisted execution.
