5. MIGRATION OPERATING MODEL
--------------------------------------------------

Migration is NOT a one-time tool.
Migration is a factory pipeline.

Pipeline:

Import → Snapshot → Layout Graph → Canonical → Quality Gate → Artifact → Shadow → Activation

Operating principles:

• linear execution
• deterministic outputs
• resumable stages
• governance-aware
• artifact-driven
• no silent fallback

Agency workflow:

1. Queue site
2. Run migration
3. Review canonical output
4. Review governance result
5. Approve activation
6. Bind domain
7. Activate runtime

--------------------------------------------------
6. RUNTIME OPERATING MODEL
--------------------------------------------------

Runtime must be:

• artifact-only
• governance-gated
• host-binding driven
• deterministic
• fail-closed

Runtime must NEVER:

• fallback to legacy builder data
• render ungoverned content
• auto-repair broken lineage
• assume migration success

Runtime must ALWAYS:

• resolve via artifact pointer
• validate governance eligibility
• produce diagnostic trace
• enforce publish stage rules

--------------------------------------------------
7. GOVERNANCE OPERATING MODEL
--------------------------------------------------

Governance is not moderation.
Governance is structural readiness enforcement.

Governance layers:

• page structural gate
• site structural gate
• rollout policy
• stage enforcement
• runtime serving eligibility

Key rule:

No governance → no serving.

Shadow stage exists to:

• validate runtime safety
• validate domain binding
• validate artifact integrity

8. OWNERSHIP OPERATING MODEL
--------------------------------------------------

• client owns published production sites

Ownership must control:

• billing attribution

• runtime publish authority
